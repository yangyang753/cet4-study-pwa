# 四级诊断估分与弱项补强设计

## 目标

把现有“基础诊断”升级为一个可恢复、可复测的综合能力测试。用户完成后获得保守的 CET-4 参考分数区间、六项能力结果和两个优先弱项；今日学习在不突破用户每日时长（默认 60 分钟）的前提下自动调整训练内容。

估分仅用于学习规划，不宣称等同于官方成绩。完整模拟考试仍是优先级更高的校准证据。

## 测试结构

一次标准诊断共 20 项：3 道高频词、3 道语法、6 道听力、6 道阅读、1 篇写作、1 篇翻译。客观题从现有原创仿真题库按“诊断开始日期 + 题目 ID”稳定抽取；同一次诊断刷新后题目不变，重新开始诊断时使用新的会话 ID 轮换题目。

写作和翻译沿用现有主观题编辑器、最低长度校验和规则化反馈。诊断页不得在测试过程中展示正确答案或参考答案。听力音频加载失败时显示重试说明，但不自动把该题判错。

## 断点续测和防重复提交

浏览器本地保存一个版本化的 `DiagnosticSession`，包含会话 ID、题目 ID 顺序、当前索引、已完成答案、主观题草稿、开始时间和最后更新时间。重新进入页面时提供“继续上次诊断”和“重新开始”；重新开始只清理未完成会话，不删除历史学习记录。

每个诊断答案以稳定 ID 保存为 `Attempt`，`mode` 为 `diagnostic`。重复点击或页面恢复不得产生重复记录。保存期间禁用提交按钮；保存失败时保留当前答案并提供重试，不前进到下一题。

## 估分与可信区间

诊断生成 `DiagnosticProfileV2`：

- `completedAt`、`sessionId`、`questionCount`；
- 六项 `levels`（0～1）；
- CET-4 四部分 `sectionScores`：写作 106.5、听力 248.5、阅读 248.5、翻译 106.5；
- `estimatedScore`、`scoreRange.low`、`scoreRange.high`；
- 排序后的 `weakSkills`，最多保留两个；
- `confidence`，初次诊断固定为 `initial`。

听力、阅读客观正确率使用加一平滑 `(正确数 + 1) / (题数 + 2)`，避免少量题目产生 0% 或 100% 的虚假确定性。写作、翻译使用现有规则评分，结果按对应官方分值权重相加并四舍五入。初次诊断区间为估分上下各 55 分，并限制在 0～710；应用明确显示“参考区间，不是官方成绩”。

词汇、语法不单独计入 710 分，但参与弱项排序。六项能力均按 0～1 比较；同分时按词汇、语法、听力、阅读、写作、翻译顺序稳定排序。

最新档案写入 `UserSettings.diagnosticProfile`，同时继续维护旧字段 `diagnosticCompletedAt` 和 `diagnosticLevels`，保证旧数据、备份和可选云同步兼容。没有 V2 档案的旧用户仍按原四项诊断结果工作。

## 今日计划适配

新增纯函数从诊断档案和最近 14 天练习记录生成两个学习优先项。每个能力必须至少有 3 次近期有效作答，才用该能力近期正确率覆盖诊断分；其他能力继续使用诊断值，避免少量单一题型过早覆盖完整诊断。

今日计划总分钟数必须始终等于用户设置：

- 词汇弱：提高词汇块分钟数；
- 听力弱：提高听力块分钟数；
- 阅读、语法、写作或翻译弱：作为当天专项任务；
- 第二弱项若已由词汇或听力固定块覆盖，显示为补强依据；否则按日期与第一弱项轮换进入专项任务；
- 错题复习继续保留；未完成任务最多顺延一个，且不得永久压住诊断弱项；
- 20 分钟短计划仍只保留词汇、听力和复习，不生成不足 5 分钟的专项任务。

任务卡显示“诊断补强”或“近期表现补强”以及具体原因。首页显示最近估分、分数区间、距 425 分差值、两个弱项和“重新诊断”入口。

## 异常和边界

- 没有足够题目时不开始诊断，显示可重试错误，不生成虚假分数。
- 无效、过期或题目已不存在的本地会话安全丢弃并重新建立。
- 写作或翻译未达到最低要求时不允许提交。
- 保存档案失败时保留完成页数据并允许重新保存。
- 估分范围必须满足 `0 <= low <= estimated <= high <= 710`。
- 日期计算使用现有学习日期工具，手机 360px 视口和离线 PWA 继续可用。

## 验收标准

- 完成标准诊断后能看到参考估分、区间、四部分分数和两个弱项。
- 中途刷新可以继续，重复提交不会重复写入。
- 当词汇、听力或写作分别为第一弱项时，今日 60 分钟计划确实增加对应内容且总时长不变。
- 近期证据只覆盖证据充分的单项；完整模拟考试结果仍独立展示并可作为更高置信度参考。
- 旧诊断、备份导入、可选同步、离线模式和现有学习记录不丢失。
- 单元测试、类型检查、代码规范、生产构建、手机端与离线端到端测试全部通过。
