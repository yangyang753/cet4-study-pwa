# CET-4 学习闭环与可靠性完善设计

## 背景与目标

“四级向前”面向英语基础薄弱、准备参加 2026 年 12 月 12 日 CET-4 笔试、每天学习 60 分钟的个人学习者。当前应用已经具备响应式 PWA、专项练习、听力、错题复习、模考、A4 打印、本地存储和可选云同步，但审查发现题目轮换、诊断排课、任务完成、模考音频、备份恢复和云端表结构之间存在断点。

本轮目标是让应用形成可信的完整学习闭环：每天选择合适且尽量不重复的练习，依据诊断和近期表现调整重点，自动记录任务与掌握状态，可靠地备份和同步，并用透明的规则提供 CET-4 备考估分。保持现有视觉风格、60 分钟日计划、离线优先架构和 GitHub Pages 部署方式。

## 成功标准

1. 同一专项不会永久重复题库开头；优先出现未做题，全部做过后优先最久未练题。
2. 词汇和语法客观题的正确选项在 A、B、C、D 间均衡分布，不能靠固定位置猜题。
3. 基础诊断会真实影响第一周计划；累计至少 5 条近期客观作答后，由最近 14 天学习证据逐渐接管薄弱项判断。
4. 基础期轮换语法、阅读、写作和翻译；语法任务与其他任务一样自动完成并触发 3 题掌握检测。
5. 所有“今日”日期按 Asia/Shanghai 计算，凌晨学习不会归到前一天。
6. GitHub Pages 上完整模考听力音频返回 200 并可播放。
7. 真实使用后导出的 JSON（包括每日计划同步操作）可以在新数据库中恢复。
8. 模考报告显示带明确免责声明的 710 分制备考估分和四个分项估分。
9. Supabase 全新项目按 001～005 迁移后，`daily_plans` 结构与客户端读写一致，不同用户可保存相同日期和题目的记录，RLS 测试计数正确。
10. 未配置云端时不显示不可用的登录、注册和找回密码表单；本地学习和备份保持可用。

## 方案选择

采用本地确定性算法，不接入付费 AI 或新的后端服务。这样可以在离线状态工作，评分和排课规则可解释、可测试，也不会增加 API 密钥、费用或学习文本上传的隐私负担。

## 题库选择与答案分布

新增独立的练习选择模块，输入专项类别、候选题、历史作答和所需数量，输出本次题目：

- 没有历史记录的题排在前面。
- 已做题按最后作答时间从旧到新排列。
- 同一优先级使用“学习日期 + 专项类别”形成稳定种子，保证当天刷新不会任意跳题，同时次日可轮换。
- 写作和翻译每次选择 1 题；客观专项默认选择 5 题。
- 掌握检测仍优先使用刚完成练习的知识点，不受日常选题轮换破坏。

词汇题和语法题在目录标准化阶段按条目索引循环移动选项，并同步计算 `correctAnswer`。四个选项时答案按 A/B/C/D 均衡；选项不足四个时按实际选项数均衡。打印、专项练习和掌握检测共享同一份标准化结果。

内容审计增加答案位置分布、重复选项和空题检查，防止以后生成内容时重新出现固定答案。

## 诊断、薄弱项与每日计划

诊断结果保存后立即参与计划生成。薄弱项来源按以下优先级决定：

1. 最近 14 天有至少 5 条可判分作答时，使用加权近期证据。
2. 数据不足且存在诊断结果时，使用诊断中最低分的类别。
3. 两者都不存在时，使用基础期预设轮换。

诊断只覆盖词汇、语法、听力和阅读，未测试的写作与翻译保存为“无数据”，不能错误地记为 0 分。诊断完成页展示四项结果和建议重点，使用户知道计划为什么变化。

基础期的 20 分钟轮换任务按日期在语法、阅读、写作、翻译之间轮换；若诊断明确显示某项薄弱，则第一周优先插入该项。突破期优先近期薄弱项；冲刺期安排模考。词汇、听力和错题复习继续作为固定日常任务。昨日未完成的非固定任务最多顺延一项，保持总时长不超过 60 分钟。

语法不再被任务完成逻辑排除。所有专项完成后写入任务完成记录，并显示掌握检测；主观题完成后把通过检查项的比例保存为 `score`，比例达到 60% 时记为本地规则评价通过，否则记为需要加强。该结果可参与近期薄弱项判断，但界面明确说明它不等同于人工批改。

## 日期与时间

建立单一的 `localStudyDate` 日期入口，所有每日计划、任务完成、模考提交、复习安排和备份文件日期均通过该入口生成。存储的事件时间继续使用 UTC ISO 时间，只有“属于哪一个学习日”的日期使用 Asia/Shanghai。

## 模考音频与估分

所有公共资源地址统一通过 `publicAssetUrl` 解析，确保根域部署和 GitHub Pages 子路径部署均能访问。端到端测试会进入模考听力分区，并对音频 URL 发起请求验证成功状态。

模考估分采用 CET-4 四部分权重：

- 写作：106.5 分（15%）
- 听力：248.5 分（35%）
- 阅读：248.5 分（35%）
- 翻译：106.5 分（15%）

听力和阅读按客观题正确率乘以对应分值。写作和翻译使用已有规则化检查项计算完成比例；空白答案为 0。总分四舍五入到整数，并展示“备考估分，不是官方换算成绩”的说明。报告同时显示距离 425 分的估计差距，但不宣称通过或替代官方成绩。

## 备份与恢复

备份 schema 将 `plan` 加入同步操作和墓碑类型。新增集成测试使用真实 `DexieLearningRepository`：保存每日计划、作答和设置，导出 JSON，再导入全新数据库并逐项核对。

导入继续使用单事务合并，校验失败时不得改变现有数据。备份版本暂时保持 1，因为新增的是当前实现本应支持但遗漏的合法操作；读取旧备份仍然兼容。

## 云同步迁移与离线账户体验

`004_daily_plans.sql` 不再依赖 `create table if not exists` 覆盖旧结构，而是显式把 001 创建的表迁移到客户端所需结构：

- `id` 改为文本并使用 `plan:<date>` 格式，主键改为 `(user_id, id)`，允许不同用户拥有同一天的计划。
- 增加 `payload jsonb`，从旧 `tasks` 和 `plan_date` 构造已有行 payload。
- 保留 `plan_date`、`updated_at`、用户外键、唯一约束、索引和 owner RLS。
- 删除不再使用的 `tasks` 列只在数据已成功迁移后执行。

新增 `005_owner_scoped_keys.sql`，把 `review_queue`、`task_completions`、`knowledge_states`、`exam_sessions` 和 `tombstones` 的文本主键统一调整为 `(user_id, id)`。这些本地 ID 包含日期或题目编号，不同用户会生成相同值，不能继续使用全局单列主键。随机 UUID 的 `attempts` 和 `drafts` 保持现有结构。

RLS SQL 测试的计划数与断言数保持一致，并验证 `daily_plans.id`、`payload`、复合主键和 owner policy。CI 在没有 Supabase 项目时继续验证 SQL 静态契约；真实跨账户验证仍需创建 Supabase 项目后执行。

账户页在 `cloudConfigured=false` 时只显示离线状态、说明和数据备份，不渲染登录表单。配置云端后才显示登录、注册和密码恢复功能。认证初始化网络异常必须回落到已退出状态并显示可重试信息，不能永久停在“恢复登录状态”。

## 错误处理与兼容性

- 音频失败继续保留当前题答案，并提供重试和文本模式。
- 题库选择在历史记录损坏或为空时安全回退到稳定轮换。
- 诊断旧设置中写作、翻译为 0 的值不参与四项诊断判断。
- 旧本地数据库通过现有 Dexie 版本迁移，无需清空数据。
- 云端迁移必须可在全新数据库按 001～005 顺序执行，也能从已执行 001～004 的数据库升级。
- 估分所需主观题文本只在本机分析；未登录时不离开设备，登录后沿用现有加密传输和 RLS 同步。

## 测试与发布

开发使用测试驱动方式，每个修复先增加能重现问题的失败测试。最低验收范围：

- 题库未做优先、最久未练、稳定日种子和答案位置均衡单元测试。
- 诊断结果驱动计划、基础期轮换、语法任务完成和北京时间边界测试。
- 模考音频子路径与 710 分制估分测试。
- 包含 plan 同步操作的备份往返测试。
- 迁移静态契约和 RLS SQL 断言测试。
- 离线账户页不显示登录表单、认证网络错误回落测试。
- 360px 手机布局、离线重开、A4 打印和既有学习流程回归测试。

完成后运行完整 `pnpm release:verify`、生产依赖安全审计和 GitHub Pages 子路径验证。合并到 `main` 并推送 GitHub，等待 Pages 工作流成功，再检查线上首页、账户页和模考音频。

## 非目标

- 不接入付费 AI、第三方作文批改或语音识别服务。
- 不声称估分等同于官方 CET-4 标准分。
- 本轮不创建 Supabase 账户或项目；代码和迁移达到可启用状态，但跨设备同步只有在用户配置项目后才会真正上线。
- 不改变现有品牌、主导航和整体视觉设计。
