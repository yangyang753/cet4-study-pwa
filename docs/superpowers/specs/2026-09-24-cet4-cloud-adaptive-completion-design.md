# 四级向前：云同步与自适应学习完善设计

## 背景与目标

现有应用已经具备每日学习、专项练习、听力、错题、限时模考、A4 打印、离线 PWA 和本地学习记录，并已部署到 GitHub Pages。检查发现，当前线上运行环境仍是“仅本机保存”，部分掌握检测没有绑定刚完成的题目，薄弱项统计可能被历史记录或内部题型名称干扰，密码找回只发送邮件而没有完成设置新密码的页面，同时首屏代码包偏大。

本轮完善的目标是让同一学习者在手机与电脑之间可靠同步，并把“完成任务—针对性检测—薄弱项补练—次日计划”形成自动闭环。目标用户英语基础薄弱，参加 2026 年 12 月 CET-4，每日计划时长为 60 分钟。

## 成功标准

- 同一邮箱账号登录手机和电脑后，学习记录、每日计划、错题、掌握状态和连续学习天数保持一致。
- 断网时仍可完成练习；恢复网络后待同步操作自动上传，不丢失作答。
- 每项任务由真实学习行为自动完成，不需要手动点击“标记完成”。
- 任务结束后出现与本次内容相关的 3～5 道掌握检测题；达到 80% 才进入已掌握状态。
- 薄弱项只从受支持的学习类别和近期有效作答中计算，不出现空白卡片或页面崩溃。
- 忘记密码流程可以从邮件链接回到应用并设置新密码。
- 手机首次打开速度改善，发布后能识别新版本并提示更新。
- 云同步、离线恢复、密码找回、手机布局和生产构建有自动化验证。

## 方案选择

采用 Supabase 免费版作为认证与云数据服务，并保留 Dexie 本地数据库作为离线主存储。该方案复用现有同步代码和迁移文件，改动面小于更换 Firebase，也能满足 GitHub Pages 静态部署。

不采用纯本地方案，因为无法满足手机和电脑同步；不更换为 Firebase，因为需要重写认证、数据模型、队列和安全策略，回归风险较高。

## 总体架构

应用采用离线优先、云端汇合的数据流：

1. 用户作答、完成任务或修改设置时，数据先写入本机 Dexie，页面立即响应。
2. 同一事务生成待同步操作，联网且已登录时由同步队列上传 Supabase。
3. 应用启动、登录、恢复网络和用户主动重试时拉取远端增量记录。
4. 合并服务按照实体类型执行追加、更新时间比较或冲突副本策略。
5. 统计服务仅读取合并后的有效学习记录，生成薄弱项、复习任务和下一日计划。

Supabase 不可用时不阻塞学习。未登录用户继续使用本地模式，界面明确显示“仅保存在本机”。

## 云端配置与安全

- 浏览器只使用项目 URL 和 `sb_publishable_...` Publishable Key；不在代码、环境变量或 GitHub 仓库中使用 `service_role` 或 Secret Key。
- 本地开发通过 `.env.local` 注入配置，GitHub Pages 通过 GitHub Actions Secrets 注入。
- 所有用户数据表启用 Row Level Security，以认证用户 ID 限制查询和写入。
- 数据库结构由 Supabase CLI 迁移统一管理；现有 `001`、`002`、`003` 迁移全部纳入部署说明和自动检查。
- README 提供从创建免费项目、取得 Project URL 和 Publishable Key、执行迁移到配置 GitHub Secrets 的完整步骤。
- 账号和 Supabase 项目由用户本人创建；实现过程不要求用户提供密码、Secret Key 或管理员令牌。

## 同步数据范围

云端同步以下用户数据：

- 客观题和主观题作答记录。
- 错题复习卡、复习阶段和错误原因。
- 每日计划、任务状态和完成来源。
- 掌握检测结果与知识点掌握状态。
- 写作、翻译草稿及更新时间。
- 模拟考试会话和结果。
- 收藏、用户设置、考试日期和每日学习时长。
- 连续学习天数所需的有效学习事件。

每日计划补充稳定的同步实体 ID，并进入同步操作类型联合，解决当前计划只保存在本机的问题。

## 冲突处理

- 作答记录采用全局唯一 ID 和追加写入，按 ID 去重，不覆盖历史。
- 每日计划、设置、复习卡和掌握状态按实体 ID 合并，较新的 `updatedAt` 生效。
- 写作和翻译草稿若两端都在上次同步后修改，保留冲突副本，不静默丢弃文本。
- 删除写入带时间戳的墓碑记录，防止另一台设备把旧数据恢复。
- 同步队列自动退避重试；界面提供“重新同步”按钮。

## 同步状态界面

账户页和全局状态区统一显示：

- `仅本机保存`：未登录或未配置云端。
- `等待同步`：存在排队操作或当前离线。
- `正在同步`：正在上传或拉取。
- `已同步`：显示最近成功同步时间。
- `同步失败`：显示可理解的原因和重新同步操作。

登录新设备后先拉取远端记录，再执行合并和本地待同步上传，避免旧设备数据被空白本地库覆盖。

## 自动完成与掌握检测

### 自动完成规则

- 高频词汇：完成规定题量并提交答案。
- 听力：播放学习材料并提交该组听力题。
- 阅读、语法和错题复习：提交对应练习组。
- 写作与翻译：达到最低内容要求、完成自查并提交。
- 模拟考试：正式交卷后完成，不因仅打开页面而完成。

首页移除手动“标记完成”入口。任务状态从作答、提交和会话事件派生，并展示未开始、进行中、待检测、待补练或已掌握。

### 针对性检测

每项任务提交后，掌握检测接收本次练习的 `sourceQuestionIds` 和知识点标签，优先生成 3～5 道关联题：

- 客观题优先复用同知识点的未见题和本次错题变式。
- 听力检测绑定刚学习的音频、定位句和转折信号。
- 错题复习检测绑定原错题及相同考点题目。
- 写作与翻译使用词汇、语法、结构和内容完整度自查与规则题，不伪装成自动人工评分。
- 模拟考试按分项薄弱知识点生成检测，不把整套模考简单映射为阅读。

正确率达到 80% 标记“已掌握”；低于 80% 自动创建短补练，并在补练后重新检测。没有足够关联题时才使用同知识点通用题，同时明确标识。

## 薄弱项与每日计划

薄弱项计算使用规范化类别：`vocabulary`、`grammar`、`listening`、`reading`、`writing`、`translation`。内部题型如 `conversation`、`news`、`cloze` 必须先映射到这些类别，禁止直接作为首页任务键。

算法规则：

- 以最近 14 天或最近 30 次有效作答为主，降低久远成绩影响。
- 每个类别达到最低样本量后才显示明确薄弱结论；不足时显示“正在积累数据”。
- 普通练习、掌握检测、错题复习和模考使用不同权重，防止重复复习记录放大影响。
- 主观题只使用已定义的量表结果，不用字数直接等同能力分。
- 所有计算结果经过受支持类别校验，未知类别回退到基础补强，不允许首页崩溃。

每日 60 分钟计划结合距离考试阶段、到期错题、近期薄弱项和未完成任务生成。首次使用先完成简短基础诊断，再形成初始计划；诊断允许稍后进行，不阻塞进入应用。

## 基础诊断

首次诊断控制在 10～15 分钟，覆盖词汇、语法、听力和阅读的小样本题。结果用于确定起始难度和第一周计划，不生成虚假的 CET-4 官方分数。写作与翻译通过简短自评和基础规则检查建立初始状态。

## 写作与翻译反馈

在现有字数统计、自查清单和参考答案基础上补充：

- 写作：任务完成度、段落结构、连接表达、词汇多样性和常见语法错误提示。
- 翻译：信息覆盖、关键词、时态语态、固定搭配和句子完整性提示。
- 反馈采用“检查项 + 例句 + 修改建议”，不宣称等同官方阅卷或 AI 精确评分。
- 题目依据历年 CET-4 题型、高频主题和考点编写原创仿真内容，不复制受版权保护的整套真题。

## 密码找回

完整流程为：

1. 用户在登录页填写邮箱并请求重置。
2. Supabase 发送带应用回调地址的邮件。
3. GitHub Pages 打开专用恢复路由并识别恢复会话。
4. 用户输入并确认新密码。
5. 应用调用 `updateUser` 更新密码，成功后清理恢复状态并回到账户页。

无效、过期或已使用的链接显示明确错误，并允许重新发送邮件。恢复页面兼容 GitHub Pages 路由回退。

## 数据管理

- 保留 JSON 导出、导入和清除本机数据。
- 导入先校验格式和版本，并在写入前展示记录数量。
- 清除本机数据需要二次确认，且不默认删除云端账号数据。
- 云端数据删除作为独立高风险操作，不与退出登录混合。

## 性能与更新

- 对主要页面使用路由级懒加载，将账户、打印、模考和统计等非首屏模块拆分。
- 将较大的题库和音频元数据按学习模块加载，避免进入首页即加载全部内容。
- 构建阶段记录主要代码包体积；主入口超过约定预算时失败或报警。
- 保留 Service Worker 离线缓存，但使用版本化缓存避免旧代码与新数据结构混用。
- 检测到新版本时展示“发现更新”，由用户点击后刷新；更新失败继续使用上一版缓存。

## 错误处理

- 本地写入失败时不显示已保存，并保留当前输入供重试。
- 音频加载失败保留答案，提供重试和文本模式。
- 同步失败不回滚已完成的本地学习，只改变同步状态。
- 远端数据结构不兼容时停止该批合并、记录诊断信息并保留本地数据。
- 题库缺少引用时隔离单题，不让整个计划页面崩溃。
- 密码恢复、登录超时和会话失效均提供返回登录页的明确路径。

## 测试设计

### 单元与组件测试

- 内部题型到学习类别的规范化映射。
- 近期样本、最低样本量和权重化薄弱项算法。
- 自动完成规则和 80% 掌握门槛。
- `sourceQuestionIds` 在听力、专项、错题和模考中的传递。
- 每日计划同步序列化、合并和冲突策略。
- 密码恢复状态与表单验证。
- 未配置、离线、排队、同步中、成功和失败状态显示。

### 端到端测试

- 手机尺寸完成每日任务后自动进入针对性检测。
- 检测未通过后生成补练，通过后自动标记掌握。
- 两个浏览器上下文登录同一测试账号后同步学习进度。
- 断网作答、恢复网络、自动上传并在另一上下文出现。
- 密码重置回调页面设置新密码。
- Service Worker 更新提示和刷新流程。
- 360px 宽度下无横向溢出，键盘可完成核心操作。

云端端到端测试使用独立测试项目和测试账号，不在日志中输出凭证。

## 发布流程

GitHub Actions 按以下顺序执行：

1. 安装依赖并检查环境变量是否完整。
2. 运行内容审计、单元测试和组件测试。
3. 运行生产构建和包体积检查。
4. 在具备测试云配置时运行云同步端到端测试。
5. 成功后发布 GitHub Pages；失败则不替换当前线上版本。

数据库迁移在发布网页前单独执行并验证。网页部署不自动使用高权限数据库密钥。

## 实施顺序

1. 修复学习类别规范化和针对性掌握检测，先消除错误计划与无关检测风险。
2. 将每日计划和掌握状态纳入同步数据模型，补齐迁移与合并规则。
3. 完成 Supabase 免费项目配置、RLS、认证和跨设备同步。
4. 完成密码恢复页面和异常处理。
5. 增加基础诊断、近期薄弱项算法和写作翻译反馈。
6. 拆分代码包、增加更新提示与无障碍检查。
7. 完成自动化验证，推送 GitHub 并检查手机与电脑线上版本。

## 非目标

- 不保存或索取用户的 Supabase 登录密码、Secret Key 或 `service_role` Key。
- 不承诺官方 710 分制估分或人工等价的作文评分。
- 不复制或公开分发受版权保护的完整历年真题与音频。
- 不在本轮加入社区、排行榜、付费订阅或教师后台。

## 用户需要完成的外部步骤

用户需要在 Supabase 官网使用自己的账号创建一个免费项目，并在项目控制台取得 Project URL 和 Publishable Key。应用代码、数据库迁移、GitHub Actions 配置、测试和发布由开发流程完成。任何需要用户操作的控制台步骤均提供逐步说明，并在继续前验证结果。
