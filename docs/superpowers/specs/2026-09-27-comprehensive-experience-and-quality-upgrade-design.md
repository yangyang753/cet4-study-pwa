# CET-4 全面体验与学习质量升级设计

## 目标

在不清空、覆盖或降级现有学习记录的前提下，完成一次面向基础薄弱学习者的整体升级：重做过于简陋的桌面左侧导航，修复手机深层链接和跨设备同步边界，提高听力、阅读、写作、翻译与估分的可信度，并补齐移动端验证、内容来源、学习报告、考试日期确认和提醒能力说明。

应用继续以 2026 年 12 月四级考试为目标，保持本机优先、可离线、电脑与手机浏览器可用。任何估分只作为备考参考，不承诺实际考试通过；以最近三次完整模考最低分达到 450 作为安全目标。

## 约束

- 不删除 IndexedDB、localStorage 或已有云端学习数据。
- 不提交 Supabase 密钥、服务角色密钥、GitHub Token 或其他凭据。
- 云同步只有在部署环境同时提供 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_PUBLISHABLE_KEY` 后才能真正启用。
- 不复制受版权保护的完整官方真题；题目继续明确标注为基于 CET-4 题型与公开考点规律编写的原创仿真内容。
- 主观题本地评分必须保守，并明确其不是人工或官方阅卷。
- 所有功能须支持 360 px 手机视口、键盘操作、读屏语义和 `prefers-reduced-motion`。

## 1. 左侧学习导航

桌面侧栏从单一链接列表升级为学习控制台：

1. 顶部保留“四级向前”品牌，并增加当前备考阶段和距考试天数。
2. 导航按“每日训练”“巩固提升”“工具与账户”分组；每个入口使用统一图标容器、标题和简短说明。
3. 当前页面使用高对比选中卡片、左侧指示条和清晰的 `aria-current`，不只依赖颜色。
4. 中下部增加“今日进度”卡，展示已完成任务数/总任务数和进度条；数据来自现有 dashboard snapshot，不建立第二套状态。
5. 底部同步区改为状态卡：本机、离线、同步中、已同步、失败均有清晰文字；本机模式提供“备份数据”快捷入口。
6. 手机继续使用底部导航，但收敛为四个主入口；其余入口放入“更多”面板，避免七个入口挤成两行。

## 2. 手机直达和 PWA 路由

GitHub Pages 无法为客户端路径返回 HTTP 200，因此路由改为 Hash 路由。统一新增应用链接生成函数，所有普通 `href`、PWA `start_url`、提醒链接和错误页链接都生成 `/#/today`、`/#/review` 等地址。

旧的 `/today`、`/review` 与 `/practice/vocabulary` 由部署生成的 `404.html` 重定向到对应 Hash 地址并保留查询参数。验收以新直达链接 HTTP 200、刷新后页面不丢失、桌面图标可启动为准。

## 3. 跨设备同步与数据安全

现有 Dexie、同步队列、Supabase remote、RLS migration 和 JSON 备份继续作为唯一数据链路，不新建并行存储。

- 增加部署同步状态自检：构建摘要明确显示 `cloud` 或 `offline`，缺一项密钥时构建失败，两个都缺失时允许本机模式。
- 账户页增加“云同步启用条件”和“最后同步时间”，并在首次登录前说明本机数据的归属和合并规则。
- 自动同步在登录、联网恢复、产生新记录和手动重试时运行；冲突继续按实体更新时间与 tombstone 规则处理。
- JSON 导出/导入保留为无云环境和故障恢复方案。
- 若本机没有生产密钥，只能完成代码和部署接口，不能虚构已启用；最终开启需要站点所有者在 GitHub Secrets 中提供两项公开客户端配置。

## 4. 听力与阅读内容质量

内容审计从“数量合格”升级为“题型结构合格”。

- 听力覆盖事实细节、原因、目的、后续行动、说话人态度、推断、主旨和同义替换，不再让 150 题只复用 7 个问题模板。
- 阅读覆盖主旨、事实定位、推断、词义、指代、作者态度、段落作用和篇章结构，不再让 180 题只复用 6 个问题模板。
- 干扰项必须与原文主题相关，不使用明显无关或固定重复的选项。
- 每道题增加题型标签与原创来源说明；内容审计去除主题词后计算模板重复度，并限制任一模板占比。
- 保留 24 份音频资产和分句时间轴；当前合成音频明确标注为训练音频。真人音频只有在获得可用授权素材后才能替换。

## 5. 写作、翻译、诊断与估分

本地评分拆成可解释证据，不再仅依赖词数、标点和少量关键词。

1. 写作检查篇幅、段落、任务覆盖、句子边界、主谓结构、连接表达、重复词和明显无效填充。
2. 翻译检查核心信息单元、目标词形、谓语结构、数字/专名遗漏、句子完整性和明显复制参考答案。
3. 每项反馈记录错误类型，并将对应词汇、搭配或题目加入复习队列。
4. 一次规则检查只能标记“完成/待复测”；写作和翻译必须在后续不看答案的掌握检测中再次通过，才计入稳定掌握。
5. 基础诊断显示样本量和置信区间；主观题规则得分采用保守上限。完整模考继续用于校准，最近三次最低 450 才显示“稳定达到安全目标”。
6. 所有页面保留“不是官方标准分或人工阅卷”的说明。

## 6. 学习报告、考试设置与提醒

- 今日页增加可展开的每周报告：七日学习天数、答题量、各模块正确率、掌握/遗忘数量、模考最低分和下周优先项。
- 首次使用或考试日期仍为默认值时显示确认卡，要求根据学校通知确认考试日期与报名截止日期；确认后不重复打扰。
- 浏览器打开时继续提供定时提醒和遗漏学习提醒。
- 设置页明确说明：静态 GitHub Pages 无法在网页完全关闭后自行唤醒。真正后台 Web Push 需要可用云端项目、推送订阅表和发送端；未配置时不显示虚假的“后台提醒已开启”。

## 7. 自动化验证

- 单元测试覆盖侧栏进度、分组导航、Hash 链接、旧链接迁移、同步模式、题库模板审计、主观题保守评分、错误分类、每周报告和日期确认。
- Playwright 在 360 px 与桌面视口覆盖今日学习、听力、专项练习、错题复习、高频知识、模拟考试、账户和 A4 打印。
- 每个核心页面运行 axe serious/critical 检查，并验证无水平滚动。
- 部署验证检查根地址、Hash 深层链接、manifest、service worker 和全部 24 个音频。
- `pnpm release:verify` 与 `pnpm audit --prod --audit-level moderate` 必须通过。

## 交付顺序

1. 导航视觉和响应式结构。
2. Hash 路由、旧链接迁移与 PWA 启动地址。
3. 同步部署自检和账户说明；有密钥时启用生产云同步。
4. 题库模板与内容审计升级。
5. 主观题评分、诊断和掌握复测升级。
6. 每周报告、日期确认、提醒边界和全页面浏览器测试。
7. 全量审查、发布并验证手机线上版本。

## 验收标准

- 左侧导航在桌面形成清晰的信息层级，今日进度和同步状态可见；手机底部导航不拥挤。
- 新 Hash 直达链接首次打开和刷新均可用，PWA 从正确页面启动。
- 现有本机学习记录在升级前后保持不变。
- 有生产密钥时手机和电脑登录同一账户可同步；没有密钥时准确显示本机模式和备份路径。
- 听力、阅读模板重复度审计通过，干扰项不再明显套版。
- 主观题不会因只有词数、关键词和标点就直接标为稳定掌握。
- 每周报告、日期确认和提醒能力边界对用户可见。
- 全量单元测试、浏览器测试、内容审计、类型检查、lint、构建、PWA、GitHub Pages 与依赖安全检查全部通过。
