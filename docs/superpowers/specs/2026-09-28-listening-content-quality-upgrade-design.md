# Listening and Content Quality Upgrade Design

## Goal

Turn the listening page into a polished CET-4 training cockpit and replace structurally misleading simulated material with format-faithful original practice. The app remains designed for a weak-foundation learner studying on both phone and desktop.

## Experience design

The listening page uses a mission header, progress summary, immersive player, visible segment progress, set navigation, and a wider sticky question panel. Transcript, translation, answer choices, dictation, and mastery feedback remain separate learning stages instead of appearing as one dense form. Desktop uses a wide player plus a 400–440 px question rail; phone uses a single task-first column without horizontal overflow.

The visual system reuses the existing deep green, warm ivory, amber action color, large rounded cards, restrained shadows, and bilingual micro-labels. Controls must have visible focus states, 44 px touch targets, reduced-motion support, and remain usable at 360 px and 200% text.

## Content architecture

Listening content is generated by type. News remains a concise report, conversation contains alternating speaker turns from at least two speakers, and passage is a coherent explanatory monologue. Each set retains stable IDs and ten questions so saved attempts and review records remain valid. Audio generation alternates installed English voices for speaker-tagged conversation segments and keeps transcript timing synchronized with the resulting WAV file.

Paragraph matching becomes one coherent article with ten labeled paragraphs and ten statements. A mock selects all ten questions from one matching group; it no longer combines ten unrelated topics. Cloze remains one passage with ten blanks and a fifteen-word bank. Careful reading remains two passages with five questions each.

Writing items contain complete 120–180 word model essays, not opening sentences. Translation items contain multi-sentence Chinese paragraphs of at least 80 Chinese characters with complete English references. Content audits enforce these contracts so regeneration cannot silently restore the old placeholders.

## Learning evidence

Existing translation-before-answer gating, automatic attempt saving, wrong-answer review insertion, task completion, and mastery checks remain unchanged. The weekly score trend and explicit non-official-score disclaimer remain visible. Cloud sync and true background push remain capability-gated: without external Supabase and push-service configuration, the app must continue to state that data is device-local and reminders require the app to be open.

## Verification

Unit tests cover listening page hierarchy, type-specific transcript structure, coherent matching groups, full writing models, full translation length, audio paths, persistence, and recovery. Browser tests cover desktop, 360 px phone, 200% text, keyboard focus, audio loading, and no horizontal overflow. Release verification includes content, audio, unit, browser, type, lint, build, Pages, migrations, runtime configuration, deployment, and live mobile smoke tests.
