# 复习可靠性与内容质量改造设计

## 目标

让高频知识页的总巩固可以反复启动、刷新后恢复，并在已经学过的全部单词中轮换检测；同时修复上轮审计确认的学习节奏与题库质量问题，避免重复材料和不完整例句干扰备考。

## 总巩固状态

- 总巩固候选集包含所有 `learning`、`review`、`mastered` 高频词，不受 `nextReviewAt` 限制。
- 排序优先级为：已到期、遗忘次数较多、最久未检测。刚完成一轮的词移到候选集后部，使下一轮自动换一批。
- 每轮最多 20 个；不足 20 个时允许再次检测同一批。
- 当前轮次及完成报告保存到浏览器本地存储。刷新后恢复当前题号或完成报告。
- “开始新一轮”必须清除旧报告、创建新队列并立即显示第一题；候选集非空时按钮不得失效。
- 保存失败时保留答案和当前题，不提前推进队列。

## 学习两天、巩固一天

- 节奏依据已完成的词汇任务次数，而非自然日日期。
- 完成 0 或 1 个周期内学习日时安排新词；完成 2 个时安排纯巩固；完成巩固日后开始下一个周期。
- 跳过一天不会消耗学习日；旧数据按已完成词汇任务总数平滑接入。
- 只统计 `kind=vocabulary` 的完成记录，其他知识状态不能触发巩固日。

## 题库质量

- 内容审计新增：同一篇材料不得出现完全重复句子；常见主谓不一致模板不得出现；高频重复题干模板不得超过阈值。
- 扩写脚本不再循环十条通用填充句。普通阅读与听力使用足量且不重复的补充句；段落匹配使用与段落功能对应的独立扩展内容。
- 听力与阅读固定题干提供多种表达，避免用户通过记忆题型模板作答。
- 重新生成并同步 `listeningSets.json`、`readingSets.json` 和 `inventory.json`。

## 高频词例句

- 学习卡上的例句必须是完整、带结束标点的句子，短语型词典例证不直接展示。
- 短语型例证回退为按词性生成的完整语境句；中英文都必须完整。
- 内容审计覆盖全部 800 词，禁止不完整例证重新进入发布包。

## 外部限制

- 手机与电脑自动同步需要用户提供 Supabase 项目 URL 和公开 Publishable Key；代码不能替用户创建或猜测凭据。本次保留本地备份恢复能力和明确状态提示。
- 后台推送需要推送服务和用户通知授权；当前只能在应用打开时提醒。
- 真人多音色听力需要获得可分发、授权明确的音源。现有合成音频继续保留并明确其性质，本次强化生成与内容审计，不伪装成官方真题。

## 验证

- 单元测试覆盖第二轮、轮换、刷新恢复、保存失败和实际完成次数节奏。
- 内容测试覆盖文章内部重复、固定模板、主谓一致与完整例句。
- 完整运行内容审计、单元测试、手机/桌面端到端测试、类型检查、构建和 GitHub Pages 验证。
